사용자가 로컬 PowerShell에서 실행하고 제공한 Maven 로그를 확인했습니다.
최종 실행 완료 시각은 2026-10-21 17:35:38 KST입니다.

- Java 21.0.3, Spring Boot 3.5.7, Hibernate 6.6.33.Final
- Testcontainers 1.21.3, MySQL 8.4.11 (`mysql:8.4` 이미지)
- Maven `verify`: 테스트 8개, 실패 0, 오류 0, 건너뜀 0
- BUILD SUCCESS, 전체 빌드 41.828초

## 통과한 검증

| 시나리오 | 테스트가 확인한 조건 |
|---|---|
| 보호 없는 조회 후 갱신 | 같은 행을 읽은 두 요청이 모두 성공을 주장하는 문제 재현 |
| 낙관적 잠금 | 같은 버전을 읽은 두 요청 중 하나만 커밋, 저장 소유자는 승자와 일치 |
| 비관적 잠금 | 같은 계정에 8개 요청 중 하나만 성공, 나머지 7개는 이미 사용됨으로 거절 |
| 신규 ID 충돌 복구 | 첫 후보가 같은 8개 요청이 독립 트랜잭션 재시도로 서로 다른 8개 계정 생성 |
| 재시도 한도 | 중복 후보가 반복되면 3회 후 종료하고 추가 행 없음 |
| 동일 트랜잭션에서 예외 처리 | 제약 위반을 catch해도 rollback-only이며 정상 커밋되지 않음 |
| 다른 무결성 오류 | null ID는 중복 ID 재시도 대상으로 분류하지 않음 |
| 없는 계정 | 동시성 충돌과 구분된 예외 발생 |

## 종료 문제와 수정

최초 실행은 8개 테스트가 통과했지만 종료 중 닫힌 DB 연결 경고와
Surefire JVM 종료 시간 초과 메시지가 발생했습니다.
컨텍스트를 직접 닫는 첫 수정은 Spring의 afterTestClass 처리와 충돌해 실패했습니다.

최종 구현은 MySQL을 Spring의 컨테이너 Bean으로 등록하고 `@ServiceConnection`으로
연결합니다. 수동 `context.close()`와 JUnit의 별도 컨테이너 생명주기를 제거했습니다.
`@DirtiesContext`를 통해 테스트 클래스 종료 시 Spring이 자원을 정리하도록 했습니다.

최종 로그에서 EntityManagerFactory 종료 후 Hikari `Shutdown completed`가 확인되며,
이전의 비활성 컨텍스트 오류·닫힌 연결 경고·JVM 강제 종료 메시지는 없습니다.
중복 ID 및 null 제약 오류는 의도적인 실패 경로 테스트입니다.
Mockito의 동적 에이전트 로딩 경고는 남아 있지만 이번 실행은 성공했습니다.

## 해석 범위

이는 최신 코드의 시나리오 테스트 1회 실행 결과입니다. 장시간 부하, 처리량,
p95 응답 시간, 잠금 전략의 성능 우열은 측정하지 않았습니다.
전체 빌드 시간에는 컨테이너·앱 초기화가 포함되므로 API 처리 성능으로 사용하지 않습니다.
회사 서비스의 운영 성과가 아닌 독립 개인 프로젝트의 결과입니다.
